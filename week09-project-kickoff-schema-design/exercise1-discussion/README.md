# 自訂健康情境：使用者故事撰寫與Schema定稿

> 第9週：專案啟動：需求分析與資料庫schema設計 — 對應簡報「自訂健康情境：使用者故事撰寫與Schema定稿」段落，實作時段：85-130分鐘

## 學習目標

練習針對自訂健康情境撰寫3個符合格式的使用者故事，設計至少2張含主外鍵的schema，並請AI檢查漏洞、記錄採納情況，完整走過本週「人類設計、AI找漏洞」的協作流程。

## 操作步驟

1. 兩兩一組，從「長者跌倒示警」「慢性病回診提醒」「血糖記錄追蹤」三個情境中任選一個，或提出自訂的健康情境（需與教師確認可行性）。
2. 依照「As a... I want... so that...」格式，撰寫3個使用者故事，確保每個故事都交代清楚角色、具體功能與價值，避免寫成籠統的功能清單。
3. 根據3個使用者故事，討論並手繪/文字描述出至少2張資料表的schema草稿，標示每張表的主鍵、外鍵與主要欄位，這個階段不使用AI，純粹由組員自行設計。
4. 把定稿的schema寫成CREATE TABLE語句（可請AI協助生成語法，但欄位與表的設計仍以組員定稿為準），再用「只列出問題、不要重新設計」的prompt請AI檢查漏洞。
5. 記錄AI提出的每個問題，小組討論後決定是否採納，並在AI使用日誌中寫下採納或不採納的理由。

## 給AI的提示詞範例（starterPrompt）

> 請檢查以下資料表的schema是否有明顯設計問題（例如缺外鍵約束、缺NOT NULL、缺唯一性約束、資料型態不合理），只列出你發現的問題並簡短說明理由，不要重新設計整個schema：[貼上CREATE TABLE語句]

## 測試資料

| 情境 | 可能的核心資料表 | 至少需要的外鍵關聯 |
| --- | --- | --- |
| 長者跌倒示警 | 使用者、示警裝置、跌倒事件記錄 | 示警裝置關聯使用者、跌倒事件記錄關聯示警裝置 |
| 慢性病回診提醒 | 使用者、回診時程、回診紀錄 | 回診時程關聯使用者、回診紀錄關聯回診時程 |
| 血糖記錄追蹤 | 使用者、血糖量測紀錄 | 血糖量測紀錄關聯使用者 |

## 提示（卡關時再看，上課前請勿提前公布）

- 寫使用者故事時，先問自己「這個角色在什麼情境下會用到這個功能」，避免把角色寫成籠統的「使用者」，具體的角色描述能幫助後續schema設計更貼近真實需求。
- 設計schema時，先列出每個使用者故事需要「記住」的資訊，再判斷這些資訊該分別放進哪張表，同一種資訊不該重複出現在兩張表裡。
- 請AI找漏洞前，務必先自己檢查一次1NF/2NF/3NF，AI的建議是「第二層檢查」，不是取代自己思考的第一層檢查。

## 討論問題

- AI提出的問題中，有沒有你們一開始沒想到、但確實合理的漏洞？是哪一類（缺外鍵/缺NOT NULL/缺唯一性約束）？
- 有沒有AI建議的修正，你們小組討論後決定不採納？理由是什麼？這個決定過程如何體現「人類保留設計決定權」？
