# 除錯挑戰：找出SQL語句中的三種風險寫法

> 第7週：資料庫基礎與SQL入門 — 對應簡報「除錯挑戰：找出SQL語句中的三種風險寫法」段落，實作時段：125-142分鐘

## 學習目標

練習辨識SQL語句中的三種常見錯誤——忘記WHERE導致全表更新、JOIN條件錯誤、字串拼接造成SQL injection風險，並提出修正版本。

## 操作步驟

1. 四人一組，分別檢視下方三段「錯誤版本」SQL語句，每人負責其中一段先獨立找出問題，再向組員口頭說明。
2. 針對「忘記WHERE」的語句，討論如果這句UPDATE語句被誤執行在正式環境的資料庫，會造成什麼後果，並寫下修正後應加上的WHERE條件。
3. 針對「JOIN條件錯誤」的語句，對照第1.2節的主鍵外鍵對照表，找出正確的JOIN欄位應該是什麼。
4. 針對「字串拼接SQL injection風險」的語句，說明如果使用者輸入惡意字串（如王小明' OR '1'='1）會發生什麼事，並寫出參數化查詢的修正版本。
5. 全組合力完成三段語句的修正版本，並於課後由教師公布「修正版本」核對，確認每一處修正的理由都能清楚口頭解釋。

## 測試資料

| 錯誤類型 | 風險等級 | 後果 |
| --- | --- | --- |
| 忘記WHERE子句 | 極高風險 | UPDATE/DELETE會套用到資料表中的所有記錄，而非單一目標 |
| JOIN條件錯誤 | 中風險 | 查詢結果錯誤或遺漏資料，可能導致誤判病患用藥狀況 |
| 字串拼接SQL | 高風險（資安） | 使用者輸入可被解析成額外SQL指令，可能繞過條件查出全部資料 |

## 提示（卡關時再看，上課前請勿提前公布）

- UPDATE與DELETE語句只要忘記WHERE，就會套用到整張表的所有記錄，這是實務上最常造成重大資料損壞事故的錯誤類型之一，執行前務必先用SELECT搭配相同WHERE條件確認影響範圍。
- JOIN條件錯誤不一定會讓程式報錯，可能只是安靜地回傳錯誤或空的結果，這比直接報錯更危險，因為容易被忽略，一定要對照主鍵外鍵設計表逐一核對。
- 判斷是否有SQL injection風險的關鍵字：只要看到SQL語句中用+號或字串樣板把「使用者輸入」直接接進SQL字串裡，就該提高警覺，改用參數化查詢。
