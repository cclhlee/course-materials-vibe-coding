# 動手實作：用AI生成CRUD語句並修改WHERE條件

> 第7週：資料庫基礎與SQL入門 — 對應簡報「動手實作：用AI生成CRUD語句並修改WHERE條件」段落，實作時段：95-125分鐘

## 學習目標

練習依據手繪的資料表草圖請AI生成SQL CRUD語句，並手動修改WHERE條件以精確查詢/更新特定病患資料，訓練逐句解釋SQL的能力。

## 操作步驟

1. 延續80-95分鐘手繪的「病患／掛號記錄／用藥紀錄」三張表草圖，兩兩一組，將草圖轉換成建表需求的自然語言描述，請AI生成三張表的CREATE TABLE語句。
2. 請AI依照下方「測試資料」表格生成對應的INSERT語句，將範例資料寫入三張表。
3. 手動修改AI生成的SELECT語句WHERE子句，練習查詢「王小明的所有掛號記錄」「2026年8月以後的所有用藥紀錄」等指定條件。
4. 同組互相口頭解釋每一句SQL：SELECT查詢的是哪張表的哪些欄位？WHERE子句用什麼條件過濾？JOIN（若有使用）是依據哪個欄位關聯兩張表？
5. 換手：輪流負責打字與口頭複述，確保兩人都能完整解釋整段SQL語句的邏輯，而不是只有其中一人理解。

## 給AI的提示詞範例（starterPrompt）

> 請幫我針對「病患」「掛號記錄」「用藥紀錄」三張表（欄位如下方測試資料所示）生成PostgreSQL的CREATE TABLE語句與對應的INSERT語句，並額外生成一句SELECT語句，查詢病患ID為1的所有掛號記錄與對應的用藥紀錄（需要用JOIN）。

## 測試資料

| 資料表 | 範例資料 |
| --- | --- |
| 病患 | 病患ID=1, 姓名=王小明, 生日=1960-05-12, 性別=男 |
| 掛號記錄 | 掛號ID=101, 病患ID=1, 掛號日期=2026-08-10, 科別=家醫科 |
| 用藥紀錄 | 用藥ID=201, 掛號ID=101, 藥品名稱=Metformin, 劑量=500mg, 服用頻率=每日兩次 |

## 提示（卡關時再看，上課前請勿提前公布）

- JOIN的條件（ON子句）必須是兩張表之間真正有關聯的欄位，這裡是掛號記錄的掛號ID對應用藥紀錄的掛號ID，寫錯欄位會導致查詢結果錯誤或回傳空結果。
- WHERE子句放在JOIN之後，用來進一步限縮查詢範圍到特定病患，若忘記加WHERE，會查出所有病患的掛號與用藥紀錄。
- 口頭解釋時可以按照SQL執行的邏輯順序描述：先確定FROM哪張表、再看JOIN如何關聯、最後看WHERE如何過濾，這個順序有助於逐步拆解複雜查詢。

## 討論問題

- 如果要查詢「所有科別為家醫科、且用藥種類包含Metformin的病患姓名」，你會怎麼修改WHERE子句與JOIN條件？
- 為什麼在動手實作前要先手繪草圖，而不是直接請AI生成建表語句？這對後續除錯挑戰有什麼幫助？
