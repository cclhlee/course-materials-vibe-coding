# 從線框圖到成品：用Replit Agent生成健康量表頁面

> 第6週：網頁基礎：HTML/CSS與使用者介面 — 對應簡報「從線框圖到成品：用Replit Agent生成健康量表頁面」段落，實作時段：75-115分鐘

## 學習目標

練習把手繪線框圖轉換成具體的自然語言描述，並比對AI生成結果與原始設計的差異，訓練「需求描述能力」而非直接寫HTML。

## 操作步驟

1. 沿用65-75分鐘畫好的「健康量表填寫頁」線框圖，兩兩一組，將線框圖上的每個區塊（標題、量表題目、單選按鈕、送出按鈕）轉換成一段自然語言描述。
2. 把描述貼進Replit Agent，請它生成對應的HTML/CSS靜態頁面。
3. 對照下方「檢查清單」表格，逐項確認AI生成的頁面是否涵蓋線框圖中的每一個元素，並記錄有哪些地方AI「自行發揮」、超出你原本的線框圖設計。
4. 如果AI生成的結果遺漏了某個元素（例如忘記加上必填欄位標示），寫下具體的追問語句請AI補上，而不是自己動手用程式碼修改。
5. 組內討論：這次的落差，是因為你們的線框圖描述不夠精確，還是AI理解上的落差？下次畫線框圖時可以怎麼標註得更清楚？

## 給AI的提示詞範例（starterPrompt）

> 請幫我生成一個「健康量表填寫頁」的HTML頁面，包含：頁面標題「今日健康量表」、一組「今日情緒」單選題（選項：很好、普通、不佳，使用fieldset和legend分組）、一個「其他症狀描述」的多行文字輸入欄位（textarea）、以及一個「送出」按鈕。每個欄位都要有對應的label元素，並使用簡單的CSS讓版面置中、欄位之間有適當間距。

## 測試資料

| 線框圖元素 | 檢查項目 | 是否需要label |
| --- | --- | --- |
| 頁面標題 | 是否使用適當的標題標籤（如h1） | 否（標題不需要label） |
| 今日情緒單選題 | 是否用fieldset+legend分組，每個radio是否有label | 是 |
| 症狀描述欄位 | 是否為textarea，是否有對應label | 是 |
| 送出按鈕 | 是否為button或input type=submit | 否（按鈕文字本身即說明） |

## 提示（卡關時再看，上課前請勿提前公布）

- 描述線框圖時，明確指出「用什麼元件」（單選、多行文字、按鈕）比只說「一個問題區塊」更容易讓AI生成正確的表單元件類型。
- 如果AI生成的單選題沒有用fieldset和legend分組，可以直接引用第2.2節學到的語意標籤知識，具體指出要修正的元件名稱。
- 先確認生成結果的「結構」是否完整（有沒有漏掉欄位），再進到下一階段調整「視覺樣式」，兩件事分開檢查比較不會混淆問題來源。

## 討論問題

- 你們的線框圖與AI生成結果之間，最大的落差出現在哪裡？是版面配置、文字內容，還是元件選擇？
- 如果同一份線框圖交給另一組同學，用不同的自然語言描述方式，你預期生成結果會有多大差異？這對「需求描述能力」的重要性說明了什麼？
