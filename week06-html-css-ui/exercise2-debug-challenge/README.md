# 微調挑戰：找出並修正AI生成頁面的無障礙標籤缺陷

> 第6週：網頁基礎：HTML/CSS與使用者介面 — 對應簡報「微調挑戰：找出並修正AI生成頁面的無障礙標籤缺陷」段落，實作時段：115-140分鐘

## 學習目標

練習用瀏覽器開發者工具檢查表單欄位的label關聯，並修正AI生成頁面中常見的無障礙缺陷。

## 操作步驟

1. 延續上一個練習生成的頁面，用瀏覽器開發者工具（右鍵→檢查）打開「元素」面板，逐一點選每個輸入欄位，確認是否有對應的<label for="...">元素，且for屬性的值與輸入欄位的id完全一致。
2. 對照下方「待改進版本」，找出其中label與輸入欄位id不一致（或完全沒有label）的問題。
3. 根據課程風格規範checklist，修正無障礙標籤問題，並於課後與教師公布的「修正版本」核對。
4. 額外挑戰：使用瀏覽器的無障礙檢查工具（如Chrome開發者工具中的Lighthouse無障礙檢測），對修正前後的頁面各執行一次檢測，比較分數變化。
5. 全班分享：無障礙分數的變化，能不能單純依賴分數判斷頁面品質？還有哪些是分數無法完全反映的地方？

## 測試資料

| 檢查項目 | 待改進版本問題 | 修正方式 |
| --- | --- | --- |
| 情緒單選題 | label的for屬性寫成"mood"，但input的id是"moodOption1" | 統一id與for的值，或改用label包裹input的寫法 |
| 症狀描述欄位 | 只用placeholder顯示提示文字，沒有真正的label元素 | 新增<label for="symptoms">其他症狀描述</label> |
| 送出按鈕 | 使用<div onclick="...">送出</div>模擬按鈕 | 改用真正的<button>元素，確保可用鍵盤Tab聚焦並用Enter觸發 |

## 提示（卡關時再看，上課前請勿提前公布）

- label的for屬性值必須跟輸入欄位的id完全一致（大小寫也要相同），否則瀏覽器無法建立兩者的關聯，螢幕報讀軟體也讀不到正確的標籤。
- placeholder是「輸入前的提示文字」，使用者一開始打字後placeholder就會消失，不能取代label作為持續存在的欄位說明。
- 用<div onclick="...">模擬按鈕雖然視覺上看起來一樣，但預設無法用鍵盤Tab聚焦、也無法用Enter鍵觸發，這對只能用鍵盤操作的使用者是嚴重的無障礙問題，應一律改用<button>。

## 討論問題

- 檢查label與id是否對應這件事，能不能單靠肉眼看HTML原始碼發現？還是一定要透過開發者工具實際點選測試？
- 如果你是量表頁面未來的使用者，且必須靠螢幕報讀軟體操作，這次修正前後的頁面對你的使用經驗會有什麼差異？
