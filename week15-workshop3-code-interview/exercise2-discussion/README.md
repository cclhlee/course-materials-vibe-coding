# 自我檢核清單練習：逐項確認能否清楚解釋核心程式碼

> 第15週：實作工作坊③與個別Code Interview — 對應簡報「自我檢核清單練習：逐項確認能否清楚解釋核心程式碼」段落，實作時段：100-130分鐘

## 學習目標

學生對照第2.2節的自我準備checklist，逐項確認自己是否能在沒有AI協助的情況下，清楚解釋專案中每一段核心程式碼的邏輯與設計理由。

## 操作步驟

1. 列出自己專案中的所有核心程式碼段落（建議至少5段，包含資料庫schema、至少2個關鍵函式、1段驗證或除錯邏輯、1段前端互動邏輯）。
2. 針對每一段，逐項對照checklist的5個項目自我打勾：能否口頭說出整體行為、能否說出設計理由、能否推演需求改變、能否指出AI生成但不確定的部分、能否完全不看AI工具重述邏輯。
3. 找出checklist中「打勾最少」的1-2段程式碼，這些就是最後修正時間應優先投入的地方。
4. 針對這些較弱的段落，重新用自己的話寫下一段簡短說明（3-5句），作為Code Interview前的最後複習筆記。
5. 教師與助教依錯開排程開始進行個別Code Interview期間，尚未輪到的學生持續進行本項自我檢核與最後程式碼修正。

## 測試資料

| checklist項目 | 已完全掌握特徵 | 尚待加強特徵 |
| --- | --- | --- |
| 能否口頭說出整體行為 | 能不看螢幕流暢說出完整流程 | 只能照著螢幕上的程式碼逐字讀 |
| 能否說出設計理由 | 能舉出至少一個沒有採用的替代做法並比較 | 只能說『AI建議這樣寫』 |
| 能否推演需求改變 | 能立即說出程式碼哪裡需要調整 | 需要重新閱讀程式碼才能回答 |
| 能否指出AI生成但不確定的部分 | 能明確畫出理解的邊界 | 含糊回答『大概都懂』 |

## 提示（卡關時再看，上課前請勿提前公布）

- 自我檢核時，建議真的對著空氣或錄音口說一次，而不是只在心裡『覺得應該會』——實際開口講常會發現比想像中卡頓的地方。
- 如果某段程式碼是團隊分工中同學寫的部分，更需要優先加強檢核，因為Code Interview抽問不會考慮這段程式碼是誰寫的。

## 討論問題

- 自我檢核後，你發現哪一類checklist項目（行為說明／設計理由／需求推演／AI邊界）是自己最容易高估自己已經掌握的？
- 如果時間有限，你會優先把剩餘的修正時間投入在哪一段程式碼上？為什麼？


> 本練習為討論／口頭／書面型活動，無需程式起始檔。請直接參考上方操作步驟與測試資料於課堂進行。
