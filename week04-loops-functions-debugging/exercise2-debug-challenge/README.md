# 除錯挑戰：找出迴圈與函式中的錯誤

> 第4週：迴圈、函式與除錯基礎 — 對應簡報「除錯挑戰：找出迴圈與函式中的錯誤」段落，實作時段：110-130分鐘

## 學習目標

練習先閱讀錯誤訊息、寫下自己的假設，再決定要不要請AI解釋錯誤原因，不可直接要求AI「修好」。

## 操作步驟

1. 兩兩一組，先不要執行程式碼，直接閱讀下方「錯誤版本」，寫下你們認為有問題的行數與原因。
2. 討論完成後，將程式碼貼到Replit中執行，觀察第一個出現的錯誤訊息（ReferenceError），寫下這個錯誤訊息在說什麼。
3. 修正第一個錯誤後重新執行，你會發現程式雖然能跑，但輸出的平均分數變成NaN——這是第二個錯誤，請對照「測試資料」表格找出原因。
4. 合作修正程式碼，使其能正確處理所有測試資料，並於課後與教師公布的「修正版本」核對。
5. 換手：修正過程中請兩人輪流打字與口頭複述目前發現的問題，確保雙方都能解釋每一個修正點。

## 測試資料

| 輸入 scores | 預期平均分數 |
| --- | --- |
| [8, 6, 9, 7, 10] | 8.0 |
| [5, 5, 5, 5] | 5.0 |
| [10, 10, 10, 10, 10, 10] | 10.0 |

## 提示（卡關時再看，上課前請勿提前公布）

- 第一次執行時，程式會在第一次迴圈就丟出 ReferenceError: total is not defined——因為total從未被宣告初始值，但程式碼卻直接用+=對它累加（相當於先讀取後寫入，讀取一個不存在的變數就會出錯）。
- 修正宣告後再執行，你會發現輸出變成「平均分數：NaN」——這是因為迴圈條件用了 i <= scores.length，導致最後一次迴圈存取到scores[scores.length]（陣列中不存在的位置，值是undefined），undefined加上數字會變成NaN。
- 要同時修正兩個錯誤才能得到正確結果：先宣告let total = 0，再把迴圈條件改成i < scores.length。

## 討論問題

- 為什麼「total += scores[i]」在total未宣告時會直接丟出錯誤，而不是像忘記宣告一般變數時那樣悄悄建立一個全域變數？
- 如果你只修正了ReferenceError，卻沒發現NaN的問題，會對後續資料分析造成什麼影響？
- 除了本題的兩種錯誤，你們這組在Prompt Problems練習中還遇過哪些AI生成的迴圈或函式錯誤？
