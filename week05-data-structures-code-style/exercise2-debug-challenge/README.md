# 風格追問挑戰：把「能跑」的程式碼變成「好」的程式碼

> 第5週：資料結構與程式風格規範 — 對應簡報「風格追問挑戰：把「能跑」的程式碼變成「好」的程式碼」段落，實作時段：95-130分鐘

## 學習目標

練習辨識AI生成程式碼中常見的風格問題，並用具體、有依據的追問語句要求AI修正，而非只說「幫我改好一點」。

## 操作步驟

1. 兩兩一組，閱讀下方「風格待改進版本」，對照課程風格規範checklist，列出你們找到的至少4個風格問題（例如命名不清楚、缺乏空格、巢狀過深、未使用const/let等）。
2. 針對每一個問題，寫下一句具體的追問語句（例如「請把變數a改成更有意義的名稱，並說明為什麼原本的命名不好」），而不是籠統地說「幫我改好一點」。
3. 把追問語句實際輸入AI對話框，比較AI依據具體追問修正後的程式碼，與「修正版本」進行對照。
4. 討論：具體追問與籠統要求相比，AI回覆的修正說明品質有什麼差異？
5. 全班分享：各組列出的風格問題中，哪一項最常出現在AI生成的程式碼裡？

## 測試資料

| 風格問題類型 | 待改進版本特徵 | 業界規範建議 |
| --- | --- | --- |
| 變數命名 | 使用a、b、tmp等無意義名稱 | 使用能表達用途的具描述性名稱 |
| 宣告方式 | 使用var宣告變數 | 優先使用const，需要重新賦值時才用let |
| 字串引號 | 混用單引號與雙引號 | 統一使用單引號（依Airbnb規範） |
| 巢狀深度 | if判斷式巢狀超過3層 | 拆成獨立函式或提早return以降低巢狀 |

## 提示（卡關時再看，上課前請勿提前公布）

- 追問AI時，具體指出「哪一行」「什麼問題」「為什麼是問題」，會比籠統要求得到更精準、更有教學價值的回覆。
- 把兩層巢狀if合併成一個if搭配&&運算子（isPolypharmacy && isElderly），可以降低巢狀深度，同時提高可讀性。
- 命名建議直接說出這個函式或變數「做什麼」，例如countElderlyPolypharmacyPatients比f更能讓其他人（或半年後的自己）一眼看懂用途。

## 討論問題

- 如果AI第一次修正後，你覺得命名還是不夠清楚，你會怎麼繼續追問？請寫出第二輪追問語句。
- 業界風格規範（如Airbnb）與課程風格規範不完全相同時（例如縮排空格數），應該以哪一個為準？如何跟AI說明這個差異？
