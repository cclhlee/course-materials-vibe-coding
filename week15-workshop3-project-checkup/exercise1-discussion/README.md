# 同儕交叉檢視練習

> 第15週：實作工作坊③：專案完整性檢核與繳交前準備 — 對應簡報「同儕交叉檢視」段落，實作時段：60-100分鐘

## 學習目標

透過兩兩一組互相檢視對方專案中一段程式碼並提出問題，練習用文字與口頭雙重方式向他人清楚說明自己的設計理由，並學習辨識「好答案」應具備的三個要素。

## 操作步驟

1. 兩兩配對（可與練習專案分組不同，建議跨組配對以確保雙方對彼此程式碼不熟悉，更貼近正式繳交前的複查情境）。
2. 各自從自己的專案中選出2-3段核心程式碼（例如資料庫schema建立、一個關鍵函式），準備讓對方檢視提問。
3. 輪流擔任「提問者」與「說明者」：提問者從對方準備的程式碼中隨機指定一段，並從三大面向（功能／資安／文件，見第15週閱讀教材）中至少問2題。
4. 說明者口頭並輔以文字說明回答，提問者依「好答案的三個要素」（見hints）給予即時回饋，指出回答中缺少哪個要素。
5. 雙方交換角色，重複一次；結束後各自記錄下這次練習中被問到、答得不夠完整的地方，作為繳交前最後修正的重點。

## 提示（卡關時再看，上課前請勿提前公布）

- 好答案應包含的三個要素：（1）先講清楚『做什麼』的具體行為，不是只重複程式碼的變數名稱；（2）能講出『為什麼』的具體理由，並能對比至少一個沒有採用的替代做法；（3）若該段是AI生成，能誠實區分自己完全理解的部分與還不確定原理的部分。
- 擔任提問者時，優先挑選程式碼中『看起來理所當然但其實有設計選擇』的地方提問（例如為什麼用外鍵而不是直接存文字），這類問題最能反映對方是否真正理解。
- 如果對方答不出來，可以追問一個更小的子問題（例如『那這一行的資料型態是什麼』）來確認對方理解的邊界在哪裡，這也是繳交前自我複查時常用的追問策略。

## 討論問題

- 在這次交叉檢視中，你被問到的哪一類問題（功能／資安／文件）最難回答？為什麼？
- 擔任提問者時，你發現同學的回答最常缺少三個要素中的哪一個？
- 經過這次練習，你會對自己的專案哪一段程式碼再多做一次複習？


> 本練習為討論／口頭／書面型活動，無需程式起始檔。請直接參考上方操作步驟與測試資料於課堂進行。
