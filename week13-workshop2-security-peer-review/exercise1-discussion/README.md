# 練習1：四重視角審查實作——「校園失物招領系統」設計檢視

> 第13週：實作工作坊②：資安修補與多重視角同儕程式碼審查 — 對應簡報「練習1：四重視角審查實作——「校園失物招領系統」設計檢視」段落，實作時段：65-100分鐘

## 學習目標

分組後每人負責一個視角，針對同一份簡化專案設計摘要，各自寫出至少2條結構化審查意見，體驗四重視角如何互補、覆蓋不同面向的設計風險

## 操作步驟

1. 四人一組，先共同閱讀「校園失物招領系統」設計摘要：學生可上傳拾獲物品照片與描述（物品表：物品ID、名稱、描述、拾獲地點、拾獲時間、狀態），失主可留言認領（認領留言表：留言ID、物品ID外鍵、留言人姓名、聯絡方式、留言內容），目前畫面只有一個長長的列表頁，沒有搜尋或篩選功能，所有欄位都能留空直接送出。
2. 組內四人分別認領一個視角：系統架構師、資料庫設計者、使用者、資深工程師（若人數不足4人，可一人負責兩個視角）。
3. 各自依照第2.2至2.5節提供的結構化提問清單，套用到「校園失物招領系統」情境，寫出至少2條具體審查意見（需指出具體問題情境＋可執行建議，不能只寫『感覺不太好』）。
4. 組內輪流口頭分享自己視角的審查意見，其他組員可以追問「為什麼你會這樣建議」，練習用視角對應的理論依據來說明理由。
5. 全組共同挑出這四個視角意見中，你們認為「如果只能修一項，最優先要修」的一項，並說明理由。

## 測試資料

| 視角 | 審查提問方向 | 校園失物招領系統可能問題點 |
| --- | --- | --- |
| 系統架構師 | 規模成長時哪裡最先出問題 | 全站只有一個列表頁，物品數破千後如何查找 |
| 資料庫設計者 | 鍵與參照完整性 | 認領留言表的物品ID是否有外鍵約束 |
| 使用者 | Nielsen法則轉化提問 | 所有欄位可留空送出，是否符合錯誤預防原則 |
| 資深工程師 | 可讀性/可維護性 | 列表頁邏輯是否該拆分成搜尋、篩選、顯示等子功能 |

## 提示（卡關時再看，上課前請勿提前公布）

- 系統架構師視角可以特別關注「沒有搜尋/篩選功能」這件事——如果物品數量從10筆成長到1000筆，目前的長列表頁會不會直接讓使用者找不到自己丟的東西？
- 資料庫設計者視角可以檢查：如果一筆物品被刪除（例如已被領回並清除紀錄），對應的認領留言會發生什麼事？是否需要參照完整性規則來處理？
- 使用者視角建議實際想像自己是急著找傘的學生，走過整個留言送出流程，記錄下哪裡會讓你卡住或不確定下一步。

## 討論問題

- 四個視角中，哪個視角最先注意到「所有欄位可留空」這個問題？為什麼同一個問題會被不同視角用不同角度提出？
- 如果只能選一項優先修補，你們組選了哪一項？這個選擇反映了你們認為哪個風險最緊急？
- 套用結構化提問清單前後，你覺得自己寫出的審查意見有什麼不一樣？
