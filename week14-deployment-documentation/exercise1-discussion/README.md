# 專案部署上線＋掃描前後對照表填寫

> 第14週：部署上線與文件撰寫 — 對應簡報「專案部署上線＋掃描前後對照表填寫」段落，實作時段：75-120分鐘

## 學習目標

將自己的期末專案正式部署上線，重新執行npm audit與ZAP Baseline掃描，並填寫「掃描前後對照」表格說明修補成效。

## 操作步驟

1. 在Replit的Publishing工具中選擇Autoscale部署類型（若專案僅為靜態頁面則選擇Static），並依畫面指示完成上線設定。
2. 部署完成後，用瀏覽器實際開啟公開網址，測試至少2項核心功能是否正常運作（例如表單送出、查詢結果顯示）。
3. 在專案repo中重新執行npm audit，記錄本次結果（弱點數量與嚴重程度），並與第12-13週的紀錄並列。
4. 重新執行ZAP Baseline Scan，記錄本次PASS/WARN-NEW/FAIL-NEW的數量，並與第12-13週的紀錄並列。
5. 依第3.2節的三項要素（時間點數字、修補動作說明、未變化項目說明），填寫「掃描前後對照」表格，並具體寫出每項變化背後做了什麼修補。

## 提示（卡關時再看，上課前請勿提前公布）

- 部署前先確認資料庫連線字串等敏感資訊是否已放在Replit的Secrets中，而非直接寫在程式碼裡，這本身就是常見的資安檢查項目。
- 如果ZAP Baseline掃描的WARN-NEW項目與第12週相同，也要在對照表中寫出「暫緩處理」的理由，而不是略過不提。
- npm audit若掃到新弱點，優先嘗試npm audit fix，若無法自動修補，再手動查詢套件官方頁面確認建議升級版本。

## 討論問題

- 部署上線後，你的專案有沒有出現在開發環境中沒發現、但上線後才浮現的問題？
- 對照第12-14週的掃描結果，哪一項弱點的修補讓你覺得最有成就感？為什麼？
- 如果WARN-NEW項目一直存在沒有消失，你會如何跟同組成員或教師說明「這是可以暫緩的資訊性提示」而非「沒有認真處理」？
