# 改寫不合格的AI使用揭露報告

> 第14週：部署上線與文件撰寫 — 對應簡報「改寫不合格的AI使用揭露報告」段落，實作時段：120-140分鐘

## 學習目標

分析一份不合格的AI使用揭露報告範例，指出至少3項缺失，並依第2.2節的四項必要欄位改寫成合格版本。

## 操作步驟

1. 閱讀下方codeBuggy區塊中「不合格的AI使用揭露報告」範例。
2. 對照第2.2節表格中的「常見錯誤寫法 vs. 合格寫法」，列出這份範例至少3項具體缺失（例如：沒有列出關鍵提示詞、貢獻比例含糊、沒有說明人工修改內容）。
3. 針對每一項缺失，說明「為什麼這樣寫不合格」，並不只是複製課本上的定義。
4. 改寫成一份合格版本，四項欄位（使用的工具、關鍵提示詞、AI貢獻比例估算、人工修改內容說明）都必須具體、可檢驗。
5. 與鄰座同學互換改寫版本，檢查對方的關鍵提示詞是否為「看起來像真的對話紀錄」而非事後編造的模糊敘述。

## 提示（卡關時再看，上課前請勿提前公布）

- 「缺失」不是只挑格式問題（例如少了標題），更重要的是挑出「內容空洞、無法驗證」的部分，例如貢獻比例沒有說明估算依據。
- 改寫合格版本時，關鍵提示詞建議直接使用第2.2節或caseStudy中示範的句型結構，練習寫出「具體到能重現對話情境」的提示詞記錄。
- 如果自己真的不記得提示詞原文，這本身就是一項值得在報告中誠實揭露的限制，而不是事後編造一則聽起來合理的提示詞。

## 討論問題

- 在課堂範例中，哪一項缺失是你覺得最容易被忽略、但其實最能反映「有沒有真的理解自己用AI做了什麼」的？
- 如果你自己過去幾週的AI使用日誌沒有詳細記錄提示詞，這次練習對你未來記錄方式會有什麼改變？
- 同儕互換檢查時，對方指出你的哪一項欄位「看起來像編造的」？你會怎麼修改讓它更可信？
