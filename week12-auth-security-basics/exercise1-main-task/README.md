# 練習1：為表單新增登入驗證並執行npm audit

> 第12週：前後端整合、使用者驗證與資安基礎 — 對應簡報「練習1：為表單新增登入驗證並執行npm audit」段落，實作時段：105-135分鐘

## 學習目標

讓學生在真實專案中加入最基本的登入驗證，並學會操作npm audit、閱讀報告、嘗試修補至少一項弱點

## 操作步驟

1. 在自己（或延續用藥提醒系統）的Replit專案中，為表單新增最基本的登入驗證（可用簡化的帳號密碼比對，或以「模擬登入」方式呈現使用者身分判斷的邏輯）
2. 登入成功後，確認只有登入的使用者才能看到／修改屬於自己的資料（可用簡單的if判斷模擬權限檢查）
3. 在終端機執行npm audit，記錄目前專案的弱點數量與風險等級分布
4. 選擇至少一項弱點，嘗試用npm audit fix或手動更新套件版本修補，再次執行npm audit確認弱點數量是否下降
5. 寫下三句話說明：這次修補的是什麼弱點、為什麼會出現、修補後有什麼改變

## 測試資料

| 測試情境 | 預期結果 |
| --- | --- |
| 帳號admin/密碼1234登入 | 登入成功，可看到自己的用藥時程 |
| 帳號不存在或密碼錯誤 | 顯示通用錯誤訊息（不透露帳號是否存在） |
| 登入後嘗試編輯別人的用藥時程 | 應被拒絕（權限檢查擋下） |

## 提示（卡關時再看，上課前請勿提前公布）

- 如果一時做不到真正的資料庫層級權限檢查，先用最簡單的if判斷模擬也可以，重點是理解『為什麼要檢查』
- npm audit若顯示0項弱點也是正常結果，可以嘗試刻意安裝一個舊版套件來觀察有弱點時的畫面

## 討論問題

- 這段登入驗證程式碼在做什麼？
- 為什麼要用「通用錯誤訊息」而不是明確告知「帳號不存在」或「密碼錯誤」？
- 如果拿掉權限檢查（canEditSchedule），會有什麼風險？
